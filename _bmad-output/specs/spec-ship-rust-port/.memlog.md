topic: Port the ship skill's TypeScript scripts to one compiled Rust binary
updated: 2026-11-08T15:24
---

- (direction) Barbosa picked topic 'Port ship to Rust' and express mode (2026-11-08); worktree name says python-to-rust but ship is TypeScript today (7 scripts + lib, 1587 lines incl. test).
- (constraint) Behavioral parity: every flag, env var, key=value stdout line and exit code of the 7 scripts is preserved so SKILL.md flow keeps working; contract catalog in cli-contract.md.
- (constraint) Git and az stay subprocess calls via argument arrays, never a shell string (current ship-lib invariant).
- (constraint) Tokens only in Authorization headers, short-lived, never printed or put in URLs; Bearer git calls empty credential.helper.
- (constraint) No AI attribution in any commit, PR title or body the binary writes.
- (constraint) Azure auth order: az account get-access-token first; AZURE_DEVOPS_EXT_PAT/AZURE_DEVOPS_PAT only on 401/403 or when az is logged out. GitHub: GH_TOKEN/GITHUB_TOKEN override, else gh auth token -u <owner>, else active account.
- (constraint) Runs on Linux/WSL2 and macOS; ship-open launches Windows Edge/Chrome from WSL and Chrome/Edge on macOS.
- (constraint) Principal rule: Rust is used when a compiled binary is needed; no Python or npm/npx anywhere.
- (capability) CAP-1 detect: print platform (azure|github|unknown), remote, url, Azure org/project/repo, branch, inferred work item; SHIP_PLATFORM overrides.
- (capability) CAP-2 preflight: print commits ahead of upstream, staged/unstaged/untracked counts and scope_clean; advisory, never blocks.
- (capability) CAP-3 push: push current branch with upstream; Azure uses az Bearer first and stored credential as fallback; never force-push.
- (capability) CAP-4 pr: open PR on detected platform; on Azure verify or create+assign work items, link, optional transition, related links, tags, reviewers, completion transitionWorkItems set via update and read back.
- (capability) CAP-5 tag: add/remove/list PR tags (Azure) or labels (GitHub) by PR id.
- (capability) CAP-6 open: resolve email to browser profile from Local State, open URL in it, list profiles, remember default in ~/.config/ship/open.json.
- (capability) CAP-7 snapshot: annotated git tag on HEAD, date-named default, refuse collision with exit 3, optional push.
- (capability) CAP-8 distribution: one prebuilt binary per supported platform runs with no bun install or node_modules.
- (decision) Single binary with subcommands (ship detect|preflight|push|pr|tag|open|snapshot) is assumed; SKILL.md invocations change from 'bun scripts/ship-x.ts' to 'ship x'.
- (assumption) Assumed the TS scripts are retired after cutover rather than kept side by side.
- (assumption) Assumed the existing ship-lib tests are the parity baseline and get ported.
- (question) What forces the port: startup time, removing the bun+node_modules install step, distribution to other machines, or learning? Decides CAP-8 scope.
- (question) How is the binary distributed: committed per-platform builds, cargo install from the repo, or GitHub Releases?
- (question) Does ship-tag (the release skill) also move to Rust, or only ship?
- (question) Which crates for ADO and GitHub REST: raw HTTP client or octocrab; no official ADO Rust SDK exists to mirror azure-devops-node-api.
- (note) Non-goals: no new features during the port; no change to the PR/work-item flow; no Windows-native (non-WSL) support.
- (note) Success signal: the same ship run on one Azure Repos and one GitHub repo produces identical key=value output with the binary as with the TS scripts, on a machine without bun.
- (question) Supersedes crate question: is there a maintained Rust crate for ADO REST (e.g. azure_devops_rust_api) good enough to replace azure-devops-node-api, or call raw REST? Unverified this session; for GitHub, octocrab vs raw REST.
- (event) Self-validate pass 1 (coherence): PASS; 8 CAPs each with intent+success, 8 constraints that rule options out, 3 non-goals, testable success signal; gaps routed to 3 assumptions + 5 open questions.
- (event) Self-validate pass 2 (preservation): PASS; flags, env vars, stdout keys, exit codes and platform specifics from the 7 TS scripts landed in cli-contract.md; SKILL.md adopted as companion for flow and gotchas.
- (decision) Barbosa answered the why (2026-11-08): all four forces apply: drop bun+node_modules, distribute to other machines, startup speed, learn Rust. CAP-8 is load-bearing; Q1 closed.
